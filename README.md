# FamilyWatch セットアップ手順

## これは何をするアプリか
1. 一定間隔でFamily Linkアプリを前面に呼び出す
2. その画面をMediaProjection APIでキャプチャ
3. 端末内OCR(ML Kit)でテキスト化
4. 指定したキーワード(住所や地名の一部)が含まれていたらアラームを鳴らし続ける

## 重要な制約(先に理解してください)
- **正確な距離判定ではなく「文字列一致」判定です**。Family Linkの位置情報画面に
  表示される住所テキストにキーワードが含まれるかどうかで判定するため、
  「半径〇〇m以内」のような厳密な判定はできません。
- Family Linkの表示レイアウトはGoogle側の仕様変更で変わる可能性があり、
  その場合はOCRで拾えるテキストも変わるので調整が必要になります。
- 監視中は数秒おきに画面がFamily Linkアプリに切り替わります(チラつきあり)。
- 端末を再起動するとMediaProjectionの許可が失効するため、再起動後は
  アプリを開いて「監視を開始」を押し直す必要があります。
- バッテリー最適化の対象から本アプリを除外しないと、OSに殺されて
  監視が止まる可能性が高いです(設定 > アプリ > FamilyWatch > バッテリー
  > 制限なし、に設定してください)。
- このAPKは配布用の署名(Google Playの正式な署名)がされていない
  「デバッグビルド」です。インストール時に「提供元不明のアプリ」の
  許可が必要になります。

## ビルド不要でAPKを手に入れる方法(GitHub Actions)
Android Studioを開かずに、GitHub上で自動ビルドしてAPKをダウンロードできます。

1. GitHubアカウントを作成(無料、まだ持っていない場合)
2. GitHubで新しいリポジトリを作成(Public/Privateどちらでも可)
3. このzipの中身(FamilyWatchフォルダの中身)をそのリポジトリにアップロード
   - GitHubのWeb画面から「Add file」→「Upload files」でドラッグ&ドロップでもOK
   - フォルダ構造を保ったままアップロードしてください
4. アップロード後、リポジトリの「Actions」タブを開く
   - 自動的に「Build APK」というワークフローが走り始めます(数分かかります)
   - 走らない場合は「Actions」タブ→「Build APK」→「Run workflow」で手動実行
5. ワークフローが緑色のチェックで完了したら、そのワークフロー実行結果を開き、
   ページ下部の「Artifacts」欄から `FamilyWatch-debug-apk` をダウンロード
   (zipでダウンロードされるので展開すると中に `app-debug.apk` があります)
6. そのAPKファイルをAndroid端末に転送してインストール
   (Google Drive経由で送る、USBでコピーする、など何でもOK)
   - 初回インストール時に「このソースからのアプリのインストールを許可」を
     求められるので許可してください

これで、コードを書いたりAndroid Studioをインストールしたりせずに
APKファイルが手に入ります。

## スマホから直接開けるダウンロードURL(推奨)
「Artifacts」はログインが必要で期限も短いため、スマホのブラウザで
そのまま開ける固定URLが欲しい場合は「Releases」機能を使います。
今回のワークフロー更新により、pushするたびに `latest` という名前の
リリースが自動更新され、そこにAPKが添付されるようになっています。

ダウンロードURLは以下の形式になります(あなたのユーザー名とリポジトリ名に
置き換えてください):

```
https://github.com/<あなたのGitHubユーザー名>/familywatch/releases/download/latest/FamilyWatch.apk
```

このURLをスマホのブラウザで開けばAPKのダウンロードが始まります
(リポジトリがPublicの場合はログイン不要、Privateの場合はブラウザで
GitHubにログイン済みである必要があります)。

初回はまだ`latest`リリースが存在しないので、一度ワークフローを
実行してから(pushするか、Actionsタブから手動実行)URLを開いてください。

## (参考)Android Studioで自分でビルドする場合
1. Android Studioでこのフォルダを「Open」で開く(新規プロジェクト作成は不要、
   既にGradleプロジェクトとして必要なファイルが揃っています)
2. Gradle Syncが終わるのを待つ
3. 上部メニュー「Build」→「Build Bundle(s) / APK(s)」→「Build APK(s)」
4. ビルド完了後に出る通知の「locate」リンクからAPKファイルを取得

## 判定条件式の書き方
「判定条件式」欄には、単純な1つのキーワードだけでなく、AND/OR/NOTを組み合わせた
自由な条件式を書けます。

- `"文字列"` : ダブルクォートで囲んだ部分。OCR結果にその文字列が含まれていればtrue
- `A && B`   : AとBの両方を満たす(AND)
- `A || B`   : AかBのどちらかを満たす(OR)
- `! A`      : Aを満たさない(NOT)
- `( ... )`  : 優先順位を変えたい時に使うグループ化

優先順位は `!` > `&&` > `||` です(括弧で自由に変更できます)。

例(「柏市」を含み、かつ更新表示が新しく、かつ「新柏」は含まない場合に反応):

```
"柏市" && ("位置情報を更新しています" || "更新: 1分前" || "更新: 2分前") && (!"新柏")
```

書式が間違っている場合は、「監視を開始」を押した時にエラー内容が表示されます。

## 初回設定で確認すること

- 「監視対象アプリのパッケージ名」が正しいか確認してください。
  Family Linkの正式パッケージ名は `com.google.android.apps.kids.familylink`
  である可能性が高いですが、念のため以下で確認してください:
  - ブラウザでPlayストアのFamily Linkページを開き、URLの `id=` 以降の
    文字列を確認する
- 「判定キーワード」には、Family Linkの位置情報画面に表示される
  住所やランドマーク名の一部(例:「〇〇駅」「〇〇小学校」)を入力してください。
  一度アプリを手動で開いて、実際にどんな文言が表示されるか確認してから
  キーワードを決めるのがおすすめです。

## 動作しない場合に確認すること
- Android 12以降は「バックグラウンドからの他アプリ起動」に制限があります。
  `captureOnce()` 内の `startActivity(launchIntent)` が失敗する場合、
  本アプリを一度手動で前面に出した直後に監視を開始する、
  端末のメーカー独自の「自動起動許可」設定を確認する、などが必要な場合があります。
- OCRで期待したテキストが取れない場合は、キャプチャしたBitmapを
  一時的にファイル保存するデバッグコードを追加して、実際に何が
  写っているか確認してください。
- GitHub Actionsのビルドが失敗する場合は、「Actions」タブのログに
  エラー内容が表示されるので、そこを確認してください。
